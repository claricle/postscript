## How to work on a task

**Choosing a task.** A task is *ready* when every task in its `needs` is merged into `main`. Take the first ready task in this file that nobody has claimed.

**Claiming a task.** One task is one branch and one PR.
- Before starting, run `gh pr list --state all --search "I4-XX"`.
  - An open PR with that ID means the task is claimed; pick another.
  - A merged PR means the task is done.
- To claim it, create branch `issue-4/I4-XX-short-slug` from `main`. Push it at once and open a **draft** PR titled `I4-XX: <task title>`.
- Do not edit this file to record status. The PR's state is the status, so parallel agents never conflict on this file.

**Size.** Keep a PR small: about 200 changed lines or fewer, not counting generated data files.
- Each PR adds or changes specs that fail without the change.
- No refactors outside the task, and no formatting churn.

**Definition of done.** All of these must pass:
- `bundle exec rake`: specs and RuboCop. Don't add `.rubocop_todo.yml` entries.
- `ruby script/check_grammar.rb`, if you touched anything it checks.
- The PR body says which task it implements, what changed, and how it was verified.

Then mark the PR ready for review. Do not merge it; a human merges.

**Do not:**
- add parsanol to the gemspec;
- change the Lexer's tokens;
- edit `grammars/` (the grammar changes upstream in claricle/postscript-parg);
- push to `main`, force-push someone else's branch, or close issues.

**Library code supports Ruby 3.0.**
- Don't use `Data.define` (3.2) or the implicit `it` block parameter (3.4).
- `Struct.new(..., keyword_init: true)` is fine.
- Specs and scripts may assume 3.2 or newer where they need parsanol.

**If you are blocked** on a decision this file does not settle, write the question in the draft PR, leave it as a draft, and take another ready task.

**Known CI noise.** The `rake / tests-passed` check fails on every PR because of a token permission in the shared metanorma workflow. Ignore it. The `grammar` job needs network access.

## Data formats

These are defined here so that tasks can run in parallel.

`data/guide_operators.yml` is generated; never edit it by hand.

```yaml
# Generated by script/guide_operators.rb from the PostScript Language Guide.
# Do not edit. Regenerate: ruby script/guide_operators.rb GUIDE_CHECKOUT
guide:
  repository: claricle/postscript-guide
  commit: c45f337f0112acc6a771cdc101a663858d23ee12
operators:            # sorted by name
  abs:
    categories: [arithmetic-math]   # sorted; [] when no category links it
    level: 1                        # null when the page states none
```

`data/operator_overrides.yml` is hand-written.

```yaml
# Levels and categories the Guide does not give. Every entry has a reason.
operators:
  ashow:
    level: 1
    reason: "Guide page states no level; PLRM 3rd ed.: LanguageLevel 1"
  eq:
    categories: [relational-boolean]
    level: 1
    reason: "No Guide page; PLRM 3rd ed.: LanguageLevel 1"
```

The vocabulary is the two files merged per operator. An override's fields replace the generated ones, and an operator listed only in the overrides is included.

### I4-C1: Level violations

- **needs:** I4-B1. Decisions D3 and D4.
- **files:**
  - `lib/postscript/level_violation.rb`
  - `lib/postscript/validation/levels.rb`
  - specs.

`Validation::Levels.violations(program, level:)` walks `program.body` in source order. It descends into procedure bodies, array elements, and dictionary keys and values; it does not follow `InvokeProcedure`, whose body is checked where it is defined. It reports each operator or `UnknownOperator` whose vocabulary level is above `level` as a `LevelViolation`.

**Specs:**
- `shfill` at levels 1 and 2 is a violation, and at level 3 it is not;
- a violation nested in `{ }`, `[ ]` and `<< >>` is found;
- a user procedure name is not a violation;
- `level:` outside 1..3 raises ArgumentError.

### I4-C2: Default level from %%LanguageLevel

- **needs:** I4-C1.

**Specs:** a `%%LanguageLevel: 1` program that uses `setpagedevice` gives one violation; the same program without the header gives none.
